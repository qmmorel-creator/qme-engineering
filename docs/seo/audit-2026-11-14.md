anglaises), état de la branche `main` au commit `393c029`, plus le site en ligne pour les statuts HTTP et les mesures.

## Résultats

### Indexabilité et statuts : bon

- 129/129 URL du sitemap en **200**.
- Redirections **301** correctes : `http://` → `https://`, `www.` → domaine nu, `qme-engineering.netlify.app` → domaine,
  `/templates` → `/templates/`.
- Pages inexistantes en **404** (page Netlify par défaut, en anglais : voir « À corriger »).
- `X-Robots-Tag: noindex, nofollow` vérifié en ligne sur `/templates/gantt/`, `/admin/interets/`, `/packs/espace/`,
  `/concepts/` (non modifiés, conformément à la consigne).
- `robots.txt` déclare le sitemap ; un échec « robots-txt » de Lighthouse sur `/packs/` n'a pas été reproduit
  (fichier en 200 sur les 4 autres mesures) : échec ponctuel de téléchargement.
- `/connexion/` est en `Disallow` dans robots.txt mais n'a pas de `noindex` : si un lien externe pointe vers elle,
  Google peut indexer l'URL sans contenu. Faible enjeu ; à trancher par Quentin (voir plan d'action).

### Canonical et hreflang : bon

- Canonical présente et absolue sur les 129 pages.
- Hreflang FR/EN/x-default **réciproques** sur les 12 pages qui ont un équivalent (accueil, contact, sur-mesure/custom,
  méthode, références, templates). Les pages catalogue et packs n'ont pas d'équivalent anglais : pas de hreflang,
  ce qui est correct (le drapeau anglais renvoie vers `/en/templates/`, simple lien de navigation).
- Attribut `lang` cohérent : 123 pages `fr`, 6 pages `en`.

### Title et meta description : à améliorer (corrigé en partie)

État avant correction :
- Aucun doublon de description ; **un doublon de title** : « Contact · QME » (FR et EN) → corrigé (« Contact us · QME »).
- **117 descriptions sur 129 dépassent 160 caractères** (tronquées dans les résultats). Les title des pages catalogue
  reprenaient le nom du produit sans la requête (« Relance des impayés · Templates QME »).

Corrigé dans cette PR : les **28 pages en vente** (title ≤ 60 caractères avec la requête principale, description
≤ 156 caractères, voir `mots-cles.md`). Restent 90 descriptions longues : 68 pages « bientôt », 18 packs, accueil et
/templates/ (à traiter à la mise en vente de chaque template, ou dans un lot suivant).

### Titres (Hn) : corrigé sur le catalogue

- Un seul H1 sur chaque page.
- Saut H1 → H3 (« Ce que vous obtenez ») sur les 96 pages catalogue → passé en H2, rendu identique (règle CSS
  `.produit-texte h2`).
- Restent des sauts sur `/sur-mesure/`, `/references/`, `/en/custom/`, `/en/references/`, `/en/templates/` (lot suivant).

### Images : bon

- Aucune image sans `alt` ; textes alternatifs descriptifs avec la mention « données fictives ».
- Dimensions `width`/`height` présentes (CLS mesuré à 0), WebP, `loading="lazy"` sur les galeries (290 images).

### Maillage interne et liens cassés : bon

- **0 lien interne cassé** (vérification fichier par fichier de chaque `href` relatif).
- Les 28 boutons Acheter pointent vers les 28 produits Gumroad publiés ; les 28 prix affichés sont identiques aux prix
  Gumroad (vérifié le 14/11/2026 avec l'API Gumroad).
- Fil d'Ariane visible sur les pages catalogue et packs.
- Point faible : aucune page n'est reliée par le contenu (pas de guides) ; les pages catalogue ne se lient pas entre
  elles (« voir aussi »). Voir le plan d'action.

### Données structurées : absentes → ajoutées

Avant : **aucun JSON-LD**. Ajouté, généré depuis le contenu visible par `node outils/seo/donnees-structurees.mjs`
(et automatiquement par `outils/packs/generer.mjs` pour les packs), contrôlé par `outils/templates/seo.test.mjs` :

| Type | Pages | Règle |
|---|---|---|
| Organization + WebSite | accueil | nom, logo, e-mail public du site ; pas de `sameAs` (aucun profil social lié sur le site) |
| Product + Offer (EUR) | 28 pages en vente | prix, lien Gumroad et images repris de la page ; `InStock` ; **aucune note ni avis** |
| BreadcrumbList | 96 catalogue + 18 packs | reprend le fil d'Ariane affiché |
| FAQPage | 95 catalogue, 16 packs, /templates/ | uniquement les questions affichées dans `div.faq` (la page `revision` n'a pas de FAQ) |

Les 68 pages « Mise en vente prochaine » n'ont pas de Product : sans offre ni avis, Google le classe en erreur.
Validation : validator.schema.org, 35 pages (accueil, /templates/, /packs/, un pack, 2 pages « bientôt », les 28 pages
en vente) : **0 erreur, 0 avertissement**.

Limites à connaître :
- Depuis août 2023, Google n'affiche les résultats enrichis FAQ que pour des sites gouvernementaux ou de santé
  faisant autorité : le balisage FAQPage est valide mais ne donnera probablement pas d'affichage enrichi.
- Les fiches marchandes Google recommandent `shippingDetails` et `hasMerchantReturnPolicy` : non renseignés, faute de
  politique de remboursement écrite sur le site (ne pas inventer). Le Rich Results Test signalera probablement ces
  deux champs en avertissement non bloquant. À compléter si Quentin formalise une politique de remboursement.
- Le Rich Results Test de Google n'a pas été passé (interface web, de préférence sur l'URL en ligne) : à faire après
  déploiement (voir plan d'action).

### Autres constats

- **Aucune balise Open Graph / Twitter Card** : les liens partagés sur LinkedIn n'ont ni image ni titre maîtrisés.
  Pas un facteur de classement, mais un enjeu de clics depuis les réseaux, où QME communique déjà.
- **Page 404** : page Netlify par défaut, en anglais, sans lien vers le site.
- Le sitemap contient `lastmod` (date du dernier commit) : bon.
